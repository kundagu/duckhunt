# Тренажёр стендовой стрельбы — техническая спецификация для портирования

Документ описывает приложение настолько полно, чтобы его можно было
воссоздать с нуля на любой другой платформе (мобильное приложение, десктоп,
игровой движок, консоль и т.д.). Все числа, формулы, цвета и алгоритмы
приведены дословно из исходного кода.

Исходная реализация: чистый JavaScript + Canvas 2D, без зависимостей и без
сборки. Файлы: `index.html`, `css/style.css`, `js/settings.js`,
`js/input.js`, `js/targets.js`, `js/ballistics.js`, `js/render.js`,
`js/game.js`.

---

## 1. Общее описание

Браузерный тренажёр стрельбы по тарелочкам (clay pigeon / скит). Игрок
стоит в точке, камера вращается мышью (захват курсора, без перемещений),
в воздухе появляются летящие тарелочки, нужно попадать в них дробью из
вертикального двуствольного ружья (дуплекс).

Экраны:

1. **Главное меню** — настройки, переназначение кнопок, кнопка «Старт».
   На фоне — медленно вращающаяся сцена с тарелочками.
2. **Игра** — полноэкранная сцена, HUD, ружьё при удержании прицеливания.
3. **Пауза** — оверлей с кнопками «Продолжить» / «В меню».

Нет: таймера раунда, уровней, рекордов, противников, зданий. Счёт —
только выстрелы и попадания в текущей сессии.

## 2. Архитектура и структура кода

### 2.1. Модули

Все модули — самовызывающиеся функции, объединяющие состояние в глобальное
пространство имён `DH` (в исходнике — `window.DH`). Порядок загрузки
(скриптов) задаёт зависимости:

```
js/settings.js   → DH.defaultSettings, DH.loadSettings, DH.saveSettings,
                    DH.resetSettings, DH.bindingLabel, DH.sameBinding,
                    DH.initMenu, DH.settings
js/input.js      → DH.Input { bind(settings, handlers), attach(), detach() }
js/targets.js    → DH.V3, DH.Targets { list, particles, spawnTimer, reset,
                    destroy, update(dt, cam), radius }
js/ballistics.js → DH.Ballistics { MUZZLE_SPEED, patternRadius(barrel, dist),
                    resolveShot(origin, dir, barrel, targets) }
js/render.js     → DH.Render.draw(ctx, W, H, game)
js/game.js       → DH.game, звук, цикл, состояние, инициализация
```

Зависимости (для переноса на другой язык/платформу):

- `targets.js` нужен `ballistics` (список целей) и `render`;
- `render` зависит от `V3`, `Targets`, `Ballistics`, `settings`, `game`;
- `game` — «жилой» слой, зависит от всех;
- `settings` и `input` неотделимы от UI.

Рекомендуемое деление при портировании: **core** (математика, спавн,
баллистика, симуляция — без зависимостей от платформы) и **shell**
(ввод, рендер, звук, UI, хранилище настроек).

### 2.2. Игровой объект (состояние)

Единый структурный объект (в исходнике `game`), поля:

| Поле | Тип | Значение по умолчанию | Назначение |
|---|---|---|---|
| `state` | enum | `'menu'` | `'menu' \| 'playing' \| 'paused'` |
| `W, H, dpr` | number | — | размеры окна в CSS-пикселях; `dpr = min(2, devicePixelRatio)` |

## 3. Система координат и камера

### 3.1. Мировые координаты

- Правая тройка, единицы — **метры**.
- `X` — вправо (в стартовом взгляде), `Y` — вверх, `Z` — вперёд.
- Земля — плоскость `y = 0`. Игрок стоит в начале координат.

### 3.2. Базис камеры

Из `yaw` (ψ) и `pitch` (θ):

```
fwd   = ( sin(yaw)*cos(pitch),  sin(pitch),  cos(yaw)*cos(pitch) )
right = ( cos(yaw),             0,          -sin(yaw)            )
up    = (-sin(pitch)*sin(yaw),  cos(pitch), -sin(pitch)*cos(yaw) )
```

Ограничение тангажа: `|pitch| ≤ 83°`. Рыскание не ограничивается.

### 3.3. Ввод камеры

```
yaw   += movementX * sensitivity * 0.0022
pitch -= movementY * sensitivity * 0.0022
```

`movementX/Y` — дельта курсора в пикселях с момента предыдущего кадра
(аналог — режим относительного мышиного ввода / «pointer lock»).
`0.0022` рад/пиксель при чувствительности 1.0 (диапазон 0.2…4).

### 3.4. Перспективная проекция (собственная, не 3D-движок)

Вся отрисовка — двумерная, мировые точки сначала переводятся в систему
камеры, потом проецируются на экран:

```
focal = (H / 2) / tan(fov / 2)          // фокусное расстояние в пикселях
cx = W / 2,  cy = H / 2

// мировая точка → камера
cp.x = dot(p - cam.pos, cam.right)
cp.y = dot(p - cam.pos, cam.up)
cp.z = dot(p - cam.pos, cam.fwd)

// камера → экран (y инвертируется)
sx = clamp(cx + cp.x / cp.z * focal, -1e5, 1e5)
sy = clamp(cy - cp.y / cp.z * focal, -1e5, 1e5)
```

Ближняя плоскость `NEAR = 0.08` м: отрезки, оба конца которых ближе `NEAR`,
не рисуются; полуотрезки — линейная интерполяция до `NEAR` (клиппинг).

Линии в мире рисуются так: `camPoint → клиппинг по NEAR → проекция → moveTo/lineTo`.

## 5. Настройки

### 5.1. Схема

```json
{
  "sensitivity": 1.0,
  "speed": 72,
  "sound": true,
  "hintAim": false,
  "hintImpact": false,
  "bindings": {
    "aim":    { "type": "key",   "code": "Space" },
    "fire":   { "type": "mouse", "button": 0 },
    "reload": { "type": "mouse", "button": 2 }
  }
}
```

- `hintAim` — постоянно показывать зелёное кольцо «куда целиться» у каждой
  видимой цели.
- `hintImpact` — показывать после выстрела отметку, куда попала дробь.

### 5.2. Хранилище

Ключ: `dh.settings.v1`, значение — JSON. Аналоги на других платформах:
`UserDefaults` / `SharedPreferences` / INI-файл / реестр. Записи и чтение
обёрнуты в try/catch — недоступность хранилища не должна ронять игру.

### 5.3. Валидация при загрузке

Начинать с дефолтов, затем по полям:

- `sensitivity` — число, обрезать в `[0.2, 4]`;
- `speed` — число, обрезать в `[10, 80]`;
- `sound`, `hintAim`, `hintImpact` — строго `boolean`;
- `bindings.*` — `{type:'key', code:string}` либо `{type:'mouse', button:int}`,
  иначе оставить дефолт.

### 5.4. Привязки (rebinding)

Три действия: `aim` (удерживать), `fire`, `reload`. Любое действие можно
переназначить на клавишу или кнопку мыши.

Алгоритм переназначения:

1. Игрок жмёт на кнопку привязки → режим «Нажмите…» (перехват keydown и
   mousedown на фазе capture, `Esc` — отмена).
2. Новое привязанное действие уже занято другим действием → **обменять**
   привязки местами, иначе — просто записать.
3. Сохранить в хранилище, обновить подписи.

Подписи клавиш: `Space→Пробел`, `Escape→Esc`, стрелки символами,
`KeyX→X`, `Digit5→5`, `Numpad1→Num 1`, `F1→F1`, иначе — код как есть.
Мышь: `0→ЛКМ`, `1→СКМ`, `2→ПКК→ПКМ`, `3→Бок 1`, `4→Бок 2`,
иначе `Кнопка N+1`.

## 6. Ввод

Слушатели включаются только во время игры (`attach`/`detach`):

| Событие | Реакция |
|---|---|
| keydown | привязка `aim` совпала → `aim(true)` (без авто-повтора); `Escape` → пауза; `Space`/стрелки → `preventDefault` |
| keyup | привязка `aim` совпала → `aim(false)` |
| mousedown | кнопка `fire` → выстрел; кнопка `reload` → перезарядка; кнопка `aim` → `aim(true)`; `preventDefault` |
| mouseup | кнопка `aim` → `aim(false)` |
| contextmenu | `preventDefault` (чтобы ПКМ-перезарядка не открывала меню) |
| window blur / visibilitychange | `aim(false)` (залипание клавиши) |

Отвязка (`detach`) также выключает `aim(false)`.

**Захват курсора (pointer lock):** при старте и «Продолжить» —
`canvas.requestPointerLock()`. Потеря захвата (`pointerlockchange`) →
автопауза. Ошибка захвата → пауза с сообщением «Не удалось захватить
курсор. Нажмите „Продолжить“ ещё раз.». Ввод подключается сразу, не дожидаясь
захвата: относительное движение мыши работает и без него.

При портировании: на десктопе — относительный режим мыши
(`SetCursorPos`-хаки / Raw Input / `SDL_SetRelativeMouseMode`), на консоли —
стик; в браузере-аналоге — Pointer Lock API.

## 7. Игровой цикл

- `requestAnimationFrame`, `dt = min(0.05, (now - last)/1000)` секунд
  (защита от «прыжков» после фона).
- Состояние `playing` → `update(dt)`; иначе — фоновый обзор камеры для меню:
  `yaw += 0.035*dt`, `pitch → 0.02` (экспоненциально, `dt`-скорость),
  `aimProgress = 0`, цели тоже обновляются (летают за меню).
- Размеры: `W = innerWidth`, `H = innerHeight`, канвас
  `width = round(W*dpr)`, `dpr = min(2, devicePixelRatio)`. Рендер вызывает
  `setTransform(dpr,0,0,dpr,0,0)` — все координаты рисуются в CSS-пикселях.
- Смена размера окна — пересчёт немедленно.

### 7.1. Кадр (порядок шагов `update`)

1. `time += dt`
2. Прицеливание: `aimProgress += (target - aimProgress) * min(1, dt*9)`
   (target = 1 при удержании, 0 иначе) — оружие плавно поднимается.
3. Таймеры: `hitsPulse`, `hintTimer`, `toastTimer` — убывают до 0.
4. Жизнь отметок `impacts` (`t -= dt`, удаление при `t ≤ 0`).
5. Перезарядка: `reloadTimer -= dt`; `reloadProgress = 1 - max(0,timer)/0.95`;
   по нулю: `reloading=false`, `ammo=2`, звук клика.
6. Кламп pitch, пересчёт базиса камеры.
7. `Targets.update(dt, cam)`.

### 7.2. Переходы состояний

- **Старт**: сброс счёта/патронов/импактов, `yaw=pitch=0`, сброс целей,
  подсказка управления сверху на 6 с, запрос захвата курсора, `state='playing'`.
- **Пауза** (`Esc` или потеря захвата): `Input.detach()`, выход из захвата,
  оверлей паузы. Игра стоит полностью (симуляция не идёт).
- **Продолжить**: скрыть оверлей, снова запросить захват, включить ввод.
- **В меню**: `Input.detach()`, выход из захвата, сброс целей, показ меню.

## 8. Баллистика

### 8.1. Двустволка

- Два ствола, патронов 2. **Первый выстрел — нижний ствол (получок,
  `cylinder`), второй — верхний (чок, `choke`).**
- Перезарядка (0.95 с) всегда заряжает оба ствола полностью.
- Выстрел при `ammo == 0` → звук щелчка + тост «Нет патронов — перезарядка: …».

### 8.2. Направление выстрела

Выстрел идёт через прицельную точку (не через центр экрана):

```
focal = (H/2) / tan(fov/2)
dip   = (H * 0.20) / focal          // 20% высоты экрана вниз
dir   = normalize(cam.fwd - cam.up * dip)
origin = cam.pos
```

### 8.3. Разброс (диаметр дробового пятна, см — уже ×2 от табличных)

Табличные точки и линейная интерполяция между ними; за пределами
диапазона — экстраполяция по крайнему отрезку; дистанция не может быть < 0.

| Дистанция, м | Получок (cylinder), см | Чок (choke), см |
|---|---|---|
| 10 | 50 | 30 |
| 15 | 70 | 40 |
| 20 | 100 | 70 |
| 25 | 120 | 90 |
| 35 | 155 | 125 |

`patternRadius(barrel, dist) = см / 200` → радиус в **метрах** (деление на
200 = пополам для радиуса и /100 см→м).

### 8.4. Расчёт попаданий (`resolveShot`)

Для каждой живой цели:

```
rel   = t.p - origin
along = dot(rel, dir)
if along < 0.3: пропустить                 // цель позади/вплотную
tof      = along / 175                      // время полёта дроби
targetPos= t.p + t.v * tof                  // куда цель уедет к приходу дроби
proj     = origin + dir*along + (0, -0.5*9.81*tof², 0)   // с учётом просадки
miss     = |targetPos - proj|
hit if miss <= patternRadius(barrel, along) + t.radius
```

Попаданий может быть несколько за один выстрел. Каждая сбитая цель →
обломки, `hits++`, звук, вспышка счётчика на 0.25 с.

### 8.5. Подсказка «куда целиться» (итерационное упреждение)

4 итерации (для живого подсказки и для отметки при выстреле):

```
aimP = t.p
repeat 4 times:
    tof   = |aimP - origin| / 175
    tgt   = t.p + t.v * tof
    aimP  = (tgt.x, tgt.y + 0.5*9.81*tof², tgt.z)   // прицеливаемся выше
```

## 9. Тарелочки: спавн и движение

### 9.1. Состояние цели

```
p, v        : vec3      // позиция, скорость
mode        : string    // режим траектории
age, life   : float     // life — метаданные режима; по age цель НЕ удаляется
radius      : 0.11
thickness   : 0.05
bank, spin  : float     // наклон диска: bank += spin*dt*0.15; bank∈[-0.45,0.45], spin∈[-1.2,1.2]
px[]        : vec3[]    // шлейф: точка каждые 0.05 с, максимум 6 точек
dead        : bool
```

### 9.2. Тайминги

- `spawnTimer = 0.5` при старте; после каждого спавна — `rand(1.0, 2.6)` с.
- Спавн, только если `list.length < 3`.
- **Удаление цели:** только когда горизонтальная дальность до игрока
  `sqrt(dx² + dz²) > 30.5` м. По времени цели не умирают (никаких `age > life`).

### 9.3. Общая схема спавна

1. Выбрать режим взвешенно (см. таблицу).
2. Скорость:
   `speed = min(80, max(10, baseSpeed + rand(-2.5,2.5))) * 0.5 / 3.6` м/с
   (т.е. **вдвое медленнее настройки**, настройка — в км/ч).
3. Дистанция старта `dist = rand(10, 28)` м; знак `sgn = ±1` (зеркальные
   варианты траекторий).
4. До 30 попыток: азимут старта `cam.yaw + rand(-45°, 45°)`; построить
   `p`, `v`, `life` по режиму; если `|Δазимут| ≤ 45°` — принять.
5. Радиальный единичный вектор `r = (sin(wy), 0, cos(wy))`,
   касательный `t = (r.z*sgn, 0, -r.x*sgn)`.

### 9.4. Режимы траекторий и их веса

| Режим | Вес | Описание |
|---|---|---|
| `to` | 18 | на стрелка, через голову |
| `from` | 14 | от стрелка |
| `tan90` | 12 | касательная 90° |
| `tan60` | 10 | касательная 60° |
| `tan30` | 10 | касательная 30° |
| `parallel` | 16 | параллельно земле (в т.ч. над головой) |
| `climb10` | 10 | взлёт под 10° |
| `climb30` | 10 | взлёт под 30° |

Выбор: сумма весов = 100, `r = rand(0,100)`, вычитать веса до `r ≤ 0`.

### 9.5. Параметры режимов (псевдокод)

```
to:            p = (r*dist; y = rand(1,5))
               over = rand(0.5, 2.7)          // насколько выше головы
               aim = cam.pos + (0, over, 0)
               v = normalize(aim - p) * speed; life = 7

from:          d2 = rand(10, 22)
               p = (r*d2; y = rand(1,4))
               v = r * speed;                 // от стрелка
               life = 8

tan90/60/30:   y = rand(1.5, 4.5);  R = rand(16, 26)   // ближайшая точка пути
               c = r * R (+ y)
               ca = cos(угол)*±1, sa = sin(угол)
               d = normalize(r*ca + t*sa)               // горизонтальное
               L = rand(14, 26)
               p = c - d*L
               пока |p| > 30 && L > 8: L -= 1; p = c - d*L
               v = d * speed; life = 8

parallel:      с вероятностью 0.35 — близкий пролёт «насквозь»:
                   D = rand(16, 30); b = rand(1, 4.5); y = rand(2.5, 5.5)
                   phi = asin(min(0.95, b/D))
                   d = normalize(-r*cos(phi) + t*sin(phi))
                   p = r*D (+ y);  v = d * speed
               иначе:
                   b = rand(5, 22); y = rand(1.5, 5)
                   c = r*b (+ y)
                   L = rand(10, max(12, sqrt(max(100, 900 - b*b))))
                   p = c - t*L;  v = t * speed
               life = 9

climb10/30:    elev = 10° или 30°
               p = (r*dist; y = rand(0.8, 2.4))
               mix = rand(0.45, 0.95)
               hd = normalize(r*mix + t*(1-mix))         // горизонтальное направление
               v = (hd.x*cos(elev), sin(elev), hd.z*cos(elev)) * speed
               life = 8 (climb10) / 6 (climb30)
```

### 9.6. Движение и обновление

```
для каждой цели:
    if dead: удалить из списка
    age += dt
    p += v * dt                      // равномерно, гравитации нет
    bank += spin * dt * 0.15
    if горизонт. дальность до cam > 30.5: удалить
    каждые 0.05 с: добавить p в шлейф, держать макс. 6 точек
```

### 9.7. Разрушение (обломки)

При попадании `destroy(target)`: `dead = true`, +**16 частиц**:

```
dir = normalize(rand(-1,1), rand(-0.3,1.2), rand(-1,1))
sp  = rand(1.5, 7)
v   = target.v * 0.5 + dir * sp
size = rand(0.012, 0.035)   // м
rot  = rand(0, 2π);  rv = rand(-8, 8)   // рад/с
age = 0;  life = rand(0.9, 1.6)
dark = (rand < 0.3)                     // цвет обломка
```

Физика частиц: `v.y -= 9.81*dt`, `p += v*dt`; при `p.y < 0.02`:
`p.y = 0.02`, `v.y *= -0.3`, `v.x *= 0.7`, `v.z *= 0.7` (отскок с затуханием);
`rot += rv*dt`; удаление по `age > life`, угасание прозрачности в последние
0.4 с жизни: `alpha = (life - age)/0.4`.

## 10. Рендер (Canvas 2D)

Порядок слоёв кадра:

1. Очистка (`setTransform(dpr…)`, `clearRect`).
2. Небо + поле.
3. Цели (сортировка **сначала дальние** — по убыванию расстояния до камеры).
4. Обломки.
5. Подсказка прицеливания (зелёные кольца).
6. Отметки попаданий.
7. Ружьё.
8. HUD.

### 10.1. Небо и поле

Горизонт на экране: `horizonY = cy + tan(pitch) * focal`.

- **Небо** (если `horizonY > -H`): вертикальный градиент от верха экрана до
  `min(horizonY, H)`:
  `0 → rgb(52,116,208)`, `0.55 → rgb(120,175,230)`, `1 → rgb(206,228,245)`.
- **Земля** (если `horizonY < H`): градиент от `max(0,horizonY)` до низа:
  `0 → rgb(160,186,110)`, `0.35 → rgb(126,158,80)`, `1 → rgb(74,106,48)`.
- **Сетка поля**: линии 1 м→шаг 10 м, `i = -10…10`, линии вдоль X и Z от
  `-100` до `+100` м на `y = 0`, цвет `rgba(38,58,26,0.16)`, толщина 1 px.
- **Дымка у горизонта**: прямоугольник высотой
  `min(остаток высоты, max(24, H*0.22))`, градиент
  `rgba(214,230,215,0.85) → rgba(214,230,215,0)`.
- **Линия горизонта**: `rgba(60,84,52,0.45)`, 1 px на `horizonY + 0.5`
  (только если `horizonY ≥ 0`).

### 10.2. Тарелочка

- **Шлейф**: `rgba(255,190,140,0.20)`, толщина 2, ломаная по `px[]` + текущая
  позиция, с пропуском точек за `NEAR`.
- **Тень** (если `y > 0.15`): эллипс в проекции точки на землю,
  радиус `clamp(radius*pxPerM*1.1, 1, 120)` пикс., вертикальное сжатие ×0.35,
  цвет `rgba(30,45,22,α)`, `α = clamp(0.30 - y*0.012, 0.04, 0.30)`.
- **Диск**: эллипс с поворотом на `bank`:
  - `semiMajor = max(1.2, radius*pxPerM)`
  - `semiMinor = max(0.8, 0.5 * max(thickness, 2*radius*|view.y|) * pxPerM)`
    (`view` — единичный вектор от камеры к цели; `|view.y|` — насколько
    диск срезан взглядом «с ребра»)
  - вертикальный градиент `#ffb066 → #f07d20 (0.5) → #b8500e`
  - обводка `rgba(70,32,8,0.85)`, толщина `max(0.7, semiMajor*0.09)`
- **Обломки**: квадраты размером `clamp(size*focal/z, 0.8, 60)` px,
  поворот `rot`, цвет `#f07d20` (или `#4a2408` если `dark`), альфа по жизни.

### 10.3. Подсказка «куда целиться» (`hintAim`)

Для каждой живой цели **перед** стрелком (`dot(rel, fwd) ≥ 0.5`):

- точка = итерационное упреждение (§8.5), проекция;
- радиус кольца `clamp(focal/z * radius * 2.2, 16, 220) * pulse`,
  `pulse = 0.7 + 0.3*sin(time*6 + i*1.3)`;
- обводка `rgba(125,255,154,0.85)`, 2.5 px; центральная точка радиусом 2.5 px,
  `rgba(125,255,154,0.9)`.

### 10.4. Отметка «куда попала дробь» (`hintImpact`)

Создаётся при выстреле (см. §11.3), живёт 3 с, альфа угасает пропорционально
остатку жизни: `fade = t / 3`.

- Кольцо пятна: `rgba(255,165,80, 0.9*fade)`, 2.5 px,
  радиус `clamp(focal/z * radius, 5, 260)`.
- Крестик в центре пятна: ±7 px по обеим осям, толщина 2.
- Жёлтое «призрачное» кольцо точки упреждения (если она есть):
  `rgba(255,235,120, 0.85*fade)`, 2 px, радиус
  `clamp(focal/z * aimRadius * 2.2, 16, 220)` + точка радиусом 2.

Обе отметки **не сбрасываются** новыми выстрелами — новые добавляются в массив.

### 10.5. Ружьё (дуплекс)

Видно только при `aimProgress > 0.02`. Вся геометрия задана в процентах
высоты экрана `H`:

- `aimY = H*1.02 + (H*0.7 - H*1.02)*aimProgress` — при полном прицеливании
  верхушка мушки находится на **`H*0.7`**, то есть на 20% высоты ниже центра.
- Горизонтальные колебания: `ax = W/2 + sin(time*1.3)*sway + swayX`,
  `ay = aimY + sin(time*0.9+1.7)*sway*0.7`, где `sway = 2.0*(1-aimProgress)` px.
- Альфа: `clamp((aimProgress - 0.02)/0.2, 0, 1)`.
- Масштаб `s = (H*0.20/2)/64` — полукруг радиуса 64 «условных единиц»
  отображается в диаметр 20% высоты.
- **Цевьё**: прямоугольник от `y=64` до нижней границы экрана, ширина 128
  (= диаметр полукруга), градиент `#2b3038 → #12151a`, обводка `rgba(0,0,0,0.6)`
  1.5 px.
- **Полукруг** (ствол сверху): верхняя половина окружности радиуса 64,
  градиент `#3c434d → #22262d`, обводка та же.
- **«Размыкание» при перезарядке**: вертикальный масштаб купола
  `1 - 0.35*sin(π*reloadProgress)` (сначала вниз, потом обратно).
- **Мушка**: квадрат со стороной `H*0.015` в условных единицах, цвет `#15181d`,
  в верхней точке купола (выступает вверх).
- Надпись «ПЕРЕЗАРЯДКА…» справа от оружия: `rgba(255,178,125,0.9)`,
  600 14 px, `x = ax + W*0.17`, `y = min(ay + 40*s, H - 120)`.

### 10.6. HUD

Шрифт: `"Segoe UI", system-ui, sans-serif`.

- **Индикатор патронов** (слева внизу): два квадрата 16 px, `x = 26`,
  нижний край нижнего квадрата `y = H - 58`, зазор 6 px.
  Нижний квадрат = первый выстрел (получок). Заряжен — заливка `#e8edf3`;
  пуст — обводка `rgba(232,237,243,0.35)` 1.5 px. Скругление 3 px.
- **Выстрелы** слева внизу: `ВЫСТРЕЛЫ: N`, `x = 26`, `y = H - 24`,
  700 22 px, заливка `#f2f6f0`, обводка `rgba(10,14,10,0.7)` 4 px.
- **Попадания** справа внизу: `ПОПАДАНИЯ: N`, `x = W - 26`, выравнивание вправо.
  При `hitsPulse > 0`: размер `22 + 8*sin(min(1, pulse/0.25)*π)` px,
  цвет `#ffd34d` (пульс 0.25 с).
- **Подсказки/тосты сверху**: центр `W/2`, `y = 42`, 600 16 px, заливка
  `rgba(255,255,255, 0.92*α)`, обводка `rgba(10,14,10, 0.7*α)` 4 px.
  α для тоста — `toastTimer/0.4` (fade-out 0.4 с), для постоянной подсказки —
  `min(hintTimer, 1)` (fade-in 1 с). Тост приоритетнее подсказки.

## 11. Действия игрока

### 11.1. `doFire`

Условия: `state == 'playing'` и не идёт перезарядка. При `ammo == 0` —
звук «пусто» + тост (1.6 с). Иначе:

1. `barrel = (ammo == 2) ? 'cylinder' : 'choke'`; `ammo--`; `shots++`; звук.
2. Вычислить `dir` (§8.2).
3. Если включён `hintImpact` — создать отметку (§11.3).
4. `resolveShot` → уничтожить попавшие, `hits++`, вспышка, звук попадания.
5. Если `ammo == 0` — тост «Два выстрела — перезарядка: …» (2 с).

### 11.2. `doReload`

Только в игре и не во время перезарядки: `reloading = true`,
`reloadTimer = 0.95`, звук клика. Два ствола заряжаются всегда полностью.

### 11.3. Отметка попадания (создание при выстреле)

Отображается центр дробового пятна на дистанции **ближайшей** цели перед
стволом (в конусе 25° от оси выстрела, `along` в диапазоне 1…80 м),
иначе — на 25 м:

```
impTof = impD / 175
p = origin + dir*impD + (0, -0.5*9.81*impTof², 0)
radius = patternRadius(barrel, impD)
aim    = итерационное упреждение для выбранной цели (или null)
aimRadius = радиус той цели (по умолчанию 0.11)
жизнь = 3 с
```

### 11.4. Прицеливание

`aimHeld` — флаг удержания; `aimProgress` плавно тянется к 1/0
(см. §7.1). **Зума нет** — оружие только поднимается, FOV не меняется.
Отдачи нет.

## 12. Звук

Полностью синтезируется (Web Audio). Аналоги: генерация PCM в рантайме либо
заранее свёрстанные семплы. Общая схема — «шумовой всплеск через lowpass с
экспоненциальным затуханием» + «синусоида с экспоненциальным скретчем
частоты и громкости».

- Буфер шума: белый шум, 0.4 с при частоте дискретизации устройства.
- `enabled = настройка sound`; звук инициализируется/возобновляется при старте
  (политика автоплея: контекст создаётся по жесту пользователя, `resume()`).

| Событие | Параметры |
|---|---|
| **Выстрел** | шум 0.22 с, lowpass 1100 Гц, gain 0.30; + «глухой удар»: синус 120→45 Гц за 0.22 с, gain 0.36, длительность затухания ×1.4, общая длительность ×1.5 |
| **Пусто** | синус 1250 Гц, 0.05 с, gain 0.12 |
| **Клик (перезарядка)** | синус 700→400 Гц, 0.06 с, gain 0.14 |
| **Попадание** | синус 2600→900 Гц, 0.16 с, gain 0.20; + шум 0.12 с, lowpass 3500 Гц, gain 0.10 |

Все затухания — `exponentialRampToValueAtTime(0.0001, конец)`.

## 14. Сценарии и правила (сводка для тестирования)

1. Старт → курсор захвачен, счёт 0/0, патроны 2, подсказка управления 6 с.
2. Стрелять с пустыми патронами → щелчок + тост, патроны не тратятся.
3. Два выстрела → тост о перезарядке; перезарядка занимает 0.95 с, в этот
   момент выстрелы игнорируются, ствол «размыкается».
4. `Esc` или потеря фокуса/захвата → пауза; продолжить → повторный захват.
5. Цель удаляется только при вылете горизонтально дальше 30.5 м от игрока
   (может пролететь за спиной и улететь).
6. Одновременно не более 3 целей; спавн каждые 1.0…2.6 с в секторе ±45°.
7. Попадание → 16 обломков, вспышка счётчика, звук.
8. Настройки переживают перезагрузку; «Сбросить настройки» возвращает дефолты.
9. Меню — фоновая сцена с медленным вращением камеры и живыми тарелочками.

## 15. Портирование на другую платформу

### 15.1. Что является «движком» приложения

3D-движок **не нужен**. Всё — 2D-примитивы (линии, эллипсы, прямоугольники,
текст, градиенты), которые рисуются после собственной проекции (§3.4).
Достаточно immediate-mode графики с поддержкой градиентов и альфы.

### 15.2. Маппинг платформенных возможностей

| Веб-примитив | Замена |
|---|---|
| Canvas 2D | Skia/`Canvas` (Android), `UIBezierPath`/`CALayer` (iOS), GDI+/Direct2D (Windows), `SpriteBatch` + shapes (игровой движок), `pygame`/`SDL2` renderer |
| Pointer Lock + `movementX/Y` | относительный режим мыши (SDL `SDL_SetRelativeMouseMode`, Raw Input), стик геймпада, тач-панель (см. §15.4) |
| `localStorage` JSON | `UserDefaults`, `SharedPreferences`, JSON-файл в App Data, реестр |
| Web Audio (oscillator + buffer noise + biquad) | платформенный синтез или заранее подготовленные WAV-сэмплы (выстрел, щелчок, попадание) |
| `requestAnimationFrame` | главный цикл платформы; `dt = min(0.05, now-last)` |
| DOM-оверлеи меню/паузы | UI-ткит платформы (ImGui, встроенный WebView, нативные виджеты) |
| `devicePixelRatio` | scale-фактор экрана, clamp до 2 |

### 15.3. Порядок реализации (чек-лист)

1. Математика: `V3`, базис камеры, проекция, клиппинг `NEAR`.
2. Фон: небо/поле/сетка/дымка/горизонт (проверить повороты ±83° pitch).
3. Тарелочки: режимы спавна (по одному, чтобы сверить углы), движение,
   шлейф, тень, эллипс-диск, удаление на 30.5 м.
4. Баллистика: таблица пятен, `resolveShot`, порядок стволов.
5. Ввод: относительное движение мыши + привязки (aim/fire/reload/escape).
6. Ружьё и HUD.
7. Обломки и звук.
8. Меню, настройки, сохранение, переназначение.
9. Подсказки (`hintAim`, `hintImpact`), пауза, тосты.

### 15.4. Особые случаи

- **Тач-управление** (порт на мобильные): веб-версия его не поддерживает,
  но механики готовы — для тача достаточно: свайп = вращение камеры
  (та же формула с «дельтой» позиции пальца), кнопки «Огонь»/«Перезарядка»
  в углу, удержание кнопки прицеливания. Прицельная точка остаётся на
  20% высоты ниже центра — имеет смысл сместить её к центру тач-экрана.
- **Отсутствие захвата курсора**: пауза по потере фокуса — поведение
  платформо-зависимое; на десктопе можно показывать курсор и не паузить.
- **Производительность**: сортировка целей каждый кадр (≤3 цели) и
  пакетная отрисовка линий сетки — тривиальны; сложность O(N), проблем нет.
  Ограничение `dpr ≤ 2` — сохранить (иначе перерисовка на 4K дорогая).
- **Локализация**: все строки русские, захардкожены; вынести в ресурсы.
- **Шрифт**: «Segoe UI» → системный sans-serif платформы.

### 15.5. «Договорённости», которые легко потерять при переносе

1. Выстрел идёт **не по центру экрана**, а по точке на 20% высоты ниже центра.
2. Скорость тарелочки = **половина** настройки (настройка в км/ч, деление
   на 3.6 → м/с, умножение на 0.5).
3. Тарелочки **увеличены вдвое** (Ø22 см), разброс дроби **увеличен вдвое**.
4. Скорость дроби **175 м/с** (не мгновенная) — упреждение обязательно.
5. Порядок стволов: сначала получок, потом чок; перезарядка — всегда оба.
6. Цель живёт **до вылета за 30.5 м**, а не по времени.
7. Спавн строго в секторе ±45° от взгляда.
8. Подсказки `hintAim`/`hintImpact` выключены по умолчанию.
9. `dt` ограничивается 0.05 с — на «фризах» игра замедляется, а не прыгает.
10. Все отметки попаданий складываются в список и живут по 3 с независимо
    от новых выстрелов.
